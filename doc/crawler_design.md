# 게임 정보 자동 크롤링 시스템 설계 제안

게임별로 정보(캐릭터, 아이템 등)를 자동으로 수집(Crawling)하여 데이터베이스를 최신 상태로 유지하기 위한 구조를 제안합니다.

## 1. 아키텍처 개요

**전략 패턴(Strategy Pattern)**을 사용하여 공통 크롤링 로직은 재사용하고, 각 게임 사이트별(나무위키, Fandom 위키 등) 특수한 파싱 로직은 분리합니다.

### 추천 폴더 구조

```
src/
└── crawlers/
    ├── core/                  # 공통 모듈
    │   ├── Browser.ts         # Puppeteer 브라우저 인스턴스 관리 (Singleton)
    │   └── ScraperBase.ts     # 모든 스크래퍼가 상속받을 기본 클래스 (에러 처리, 로깅 등)
    ├── scrapers/              # 게임별 구현체
    │   ├── genshin/
    │   │   ├── character.ts   # 원신 캐릭터 크롤링 로직
    │   │   └── item.ts        # 원신 아이템 크롤링 로직
    │   └── starrail/
    │       └── ...
    ├── services/
    │   └── DataSyncService.ts # 수집된 데이터를 Prisma를 통해 DB에 저장/업데이트 (Upsert)
    └── scheduler.ts           # 주기적 실행을 위한 스케줄러 (node-cron 등)
```

## 2. 주요 컴포넌트 역할

### A. Scraper (수집기)

각 게임/카테고리별로 웹사이트에 접속하여 HTML을 파싱하고, **표준화된 JSON 데이터**로 변환하여 반환합니다.

- **도구**: `Puppeteer` (동적 페이지), `Cheerio` (정적 페이지 - 속도 빠름).
- **입력**: 타겟 URL (예: 나무위키 원신 캐릭터 목록)
- **출력**: `ScrapedCharacter[]`, `ScrapedItem[]` (표준 인터페이스)

### B. DataSyncService (동기화 서비스)

스크래퍼가 가져온 데이터를 받아 데이터베이스(Prisma)에 저장합니다.

- 이미 존재하는 데이터면 `update`, 없으면 `create` (Upsert).
- 변경 사항이 있는 경우에만 업데이트하여 DB 부하 최소화.

### C. Scheduler (스케줄러)

- 매일 새벽 3시 등 특정 시간에 크롤링 작업 트리거.
- 게임별로 순차적 또는 병렬로 작업 큐잉.

## 3. 구현 프로세스 예시 (원신 캐릭터)

1.  **목록 수집**: 나무위키/공식 위키의 "원신/캐릭터" 분류 페이지 접속.
2.  **상세 수집**: 각 캐릭터 링크로 들어가 상세 정보(속성, 무기, 스킬 설명, 이미지 등) 파싱.
3.  **데이터 정제**: "불 원소" -> `Element: Pyro` 매핑 등 데이터 정규화.
4.  **저장**: `DataSyncService`를 통해 `Character` 테이블 업데이트.

## 4. 고려사항

- **차단 회피**: 너무 빠른 요청은 차단될 수 있으므로 `delay` 추가.
- **이미지 처리**: 이미지 URL을 수집하거나, 필요시 서버에 다운로드하여 로컬(`static/`)에 저장.
- **사이트 변경 대응**: 대상 사이트 구조 변경 시 해당 스크래퍼만 수정하면 되도록 모듈화.
